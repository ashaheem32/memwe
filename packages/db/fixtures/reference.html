frobnicate

frobnicate, frob — adjust the frobnication level of a widget

Synopsis

frobnicate [ --level n ] [ --dry-run ] widget [, ...]

Description

Step 1: the requested level is located in the registry, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 2: the requested level is validated against the declared range, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 3: the requested level is written to the widget, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 4: the requested level is recorded for reversal, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 5: the requested level is reported to observers, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 6: the requested level is summarised on standard output, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 7: the requested level is checked against the audit policy, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 8: the requested level is mirrored to the standby registry, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 9: the requested level is compared with the previous level, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 10: the requested level is annotated with the operator's reason, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 11: the requested level is queued for the nightly consolidation, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Step 12: the requested level is confirmed by the widget itself, and if this step cannot complete for a reason the operator can act on, the command stops here, reports which widget was affected, explains what was expected, and exits with a status that distinguishes a configuration problem from a transient one, so that a retry is only attempted when it can succeed.

Options

--level n — Sets the target frobnication level for every widget named on the command line. This option may be given at most once; giving it twice is reported as an error rather than silently taking the last value, because in batch scripts the second occurrence is almost always a copy-and-paste mistake rather than an intention.

--dry-run — Reports what would change without changing anything, which is the safe way to preview a batch. This option may be given at most once; giving it twice is reported as an error rather than silently taking the last value, because in batch scripts the second occurrence is almost always a copy-and-paste mistake rather than an intention.

--override — Skips the range check and marks the widget as overridden until the override is cleared. This option may be given at most once; giving it twice is reported as an error rather than silently taking the last value, because in batch scripts the second occurrence is almost always a copy-and-paste mistake rather than an intention.

--reason text — Records why the change was made, and is required when a change crosses a range boundary. This option may be given at most once; giving it twice is reported as an error rather than silently taking the last value, because in batch scripts the second occurrence is almost always a copy-and-paste mistake rather than an intention.
